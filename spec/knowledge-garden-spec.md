# Knowledge Garden — 個人ナレッジベース(公開デジタルガーデン)仕様書 (v2)

> このドキュメントは旧 `works-portal-spec.md` (v1) を**置き換える**。
> 壁打ちの結果、主役が「作品カタログ」から「自分用の知識ベース」へ変わり、
> 配信も「自宅 Raspberry Pi」から「クラウド静的ホスト」へ変わった。
> 判断の背景は各セクションの引用ブロックに残す。

## 概要

AI と何かを作る過程で得た知見・ノウハウを **自分用に貯めていく知識ベース**。
主目的は自分のためだが、見られても構わないので **公開デジタルガーデン** として
出す。ノート(知見の蓄積)が主役で、作品はその中の1ビュー。静的サイトとして
ビルドし、git push でクラウドに自動デプロイして完結させる。コンテンツ追加は
「会話で得た知見を Claude が Markdown ノートとして追記・commit する」運用を前提と
し、人間が管理画面を触る仕組みは作らない。参考: [TNKS1407](https://tnks1407.com/)
(Astro + Cloudflare Pages 構成)。

> **なぜ v1 から変えたか:** v1 は作品カタログを主役に据え、docs とデイリーブログを
> 裏方として足し込み、自宅 Pi で配信する構成だった。だが本当に欲しかったのは
> 「知見の蓄積(セカンドブレイン)」であり、主従が逆さまだった。主役が変わると、
> v1 で「不要」としていた検索・タグ・ノート間リンクが逆に**核**になり、
> 重いインフラ(Pi・Caddy・cloudflared)は不要になる。

## システム構成

```
[閲覧者 / 自分]
     │ https
     ▼
[クラウド静的ホスト]           [GitHub リポジトリ]
  Cloudflare Pages       ◀── git push ──  ・Markdown ノート (src/content/)
  もしくは GitHub Pages       (自動ビルド)  ・Astro プロジェクト
     ▲                                     ・frontmatter スキーマ (Content Collections)
     │ 静的配信(HTML/CSS/JS)
     └─ Pagefind による全文検索(クライアント側・バックエンド不要)

[Claude (claude.ai / Claude Code)]
  会話で得た知見 → md ノートを src/content/ に書き出し → commit / push
```

- **入口は git push のみ。** ホストが push を検知して自動ビルド・デプロイする
- サーバープロセス・常駐・ポート開放は一切なし。落ちない・無料・管理不要
- 全文検索もクライアント側(Pagefind)で完結。動的バックエンドを持たない

> **なぜ自宅 Pi をやめたか:** 憧れた参考元の完成度は「自宅サーバーで頑張った結果」
> ではなく、Astro をクラウド静的ホストにポン置きした結果だった。Pi 配信は停電・
> 回線断で落ち、運用も重い。静的ホストなら SLA を気にせず、コストゼロで理想の
> 完成度に届く。ホスティング先はユーザーにこだわりが無いため実装時に選ぶ
> (推奨は Cloudflare Pages、理由は未確定事項参照)。

## コンポーネント仕様

### 1. ノート(コアコンテンツ)

- `src/content/notes/` 配下に Markdown / MDX を置く。1 ファイル = 1 ノート
- frontmatter を **Astro Content Collections の zod スキーマで検証**する。壊れた
  frontmatter はビルドが失敗して弾かれる(v1 の自前 JSON スキーマ検証はこれで代替)
- frontmatter(案):

```yaml
title: ノートのタイトル
date: 2026-07-18
tags: [astro, cloudflare]
type: note        # note | work            (省略時は note)
summary: 一覧やOGに出す1〜2行(任意)
# --- type: work のときだけ使う追加フィールド ---
status: published # published | wip | planned
url: https://...  # 公開作品のURL(任意)
repo: https://... # リポジトリ(任意)
emoji: 🧲         # 一覧アイコン(任意)
```

- **すべてを「ノート」に統一**し、作品は `type: work` のノートとして扱う。これで
  カタログとドキュメントを別立てにせず、1 つのコンテンツモデルで回す

> **なぜ統一したか:** 知識ベースが主役なので、「作品」は独立した別物ではなく
> 「"作った"という種類のノート」に過ぎない。型を分けると更新運用が二重になる。

### 2. 一覧・ナビゲーション

- **ノート一覧**: 新しい順。タイトル・日付・タグ・summary を表示
- **タグページ**: `/tags`(全タグ)、`/tags/<tag>`(そのタグのノート一覧)。
  セカンドブレインの回遊はタグが軸
- **作品ビュー**: `/works` 等で `type: work` のノートだけを抽出したインデックス。
  作品カタログは「独立サイト」ではなく「ノートの絞り込みビュー」に格下げ
- **全文検索**: Pagefind でクライアント側全文検索。KB では検索が核なので v1 に含める

> **なぜ検索を v1 に入れるか:** v1(旧仕様)は「検索は不要」としていたが、
> 主役が知識ベースに変わった以上、貯めたノートを引ける検索は最優先機能になる。

### 3. 知見の追記フロー(Claude 運用)

- 会話で知見が溜まったら、Claude が `src/content/notes/<slug>.md` を書き出し、
  frontmatter を付けて commit / push する。ホストが自動デプロイする
- 「md を 1 個置く → push → 反映」以上の手順を人間に要求しない
- 将来的にこの手順を **note-publisher スキル**として型化する(Phase 3)。旧
  `work-publisher-skill-spec.md` は、作品専用から「ノート全般の追記」へ一般化して
  作り直す

### 4. 見た目

- ミニマル。読みやすさ最優先(KB は読む時間が長い)。ライト/ダーク両対応
- Astro のブログテンプレートが持つ SEO(canonical / OG)・サイトマップ・RSS の
  素地を活かす。凝った装飾より情報設計(タグ・検索・導線)を優先

## 非機能・開発方針

- **スタックは Astro**(参考元と同じ)。TypeScript・Content Collections・MD/MDX。
  npm / Node が前提になる(v1 の「ゼロ依存」方針は撤回。理由は下記)
- 設定値(サイト名・ベースURL・著者)は Astro の設定/環境変数に 1 箇所集約
- コンテンツとテンプレートを分離。ノート追加でテンプレートを触らない
- 公開デジタルガーデンなので、全コンテンツは公開前提で書く(秘密情報を置かない)

> **なぜ「ゼロ依存の素 HTML」から Astro に変えたか:** 旧仕様は「何年後でも動く」を
> 理由に素の HTML/JS + 自前 Markdown 変換を選んだ。だが憧れた完成度(タグ・検索・
> RSS・OG・良い DX)を自前で積むと結局フレームワーク相当を再発明することになり、
> Astro に乗る方が速く・堅く・拡張しやすい。ビルド環境が要る点は許容する。

## 開発の進め方(フェーズ分け)

1. **Phase 1 — ローカルで完結(ハード・ドメイン不要)**
   Astro プロジェクトを作り、次をローカル(`npm run dev` / `build`+`preview`)で
   確認できる状態にする:
   - Content Collection `notes`(zod スキーマで frontmatter 検証)
   - ノート一覧 / ノート詳細ページ
   - タグページ(`/tags`, `/tags/<tag>`)
   - 作品ビュー(`type: work` の抽出インデックス)
   - Pagefind による全文検索
   - ライト/ダーク、最小スタイル
   - 種データ: 旧 `portal/works.json` の 3 件を `type: work` ノートに変換 + サンプル
     ノート数本
2. **Phase 2 — 公開**: クラウド静的ホスト(Cloudflare Pages 推奨)に接続し、
   git push で自動デプロイ。独自ドメインは任意で後付け
3. **Phase 3 — 追記運用の型化**: note-publisher スキル実装。会話→ノート案生成→
   承認→md 追記・commit を固定手順にする
4. **Phase 4 — デジタルガーデン強化**: ノート間リンク / バックリンク(`[[wikilink]]`)、
   関連ノート表示、RSS / OG の作り込み
