# サイト v3 — ダッシュボードを軸に据える

**2026-08-26 の議論から。** 実装は別途。ここは形と理由だけ。

## いまの何が困っているか

数えた結果（2026-08-26）:

```
seeds    1本   ← 入口が動いていない
garden   6本   ← うち2本が非公開
log      5本
works    3本   ← **STATE.md には8プロジェクトある**
```

1. **`works` が現実の37%しか見せていない。** 手書きの散文なので増えない
2. **道具22本・Skill 3・サブエージェント5・フック3に置き場が無い。**
   別リポジトリに置くしかなかった
3. **`STATE.md` が一番よく更新されるのに、4層の外にある**
4. **読み手が2種類いる。** 自分（探す）と他人（読む）

## 決めたこと: 2つの軸を交差させる

**4層モデルは「書いたもの」の分類としては正しい。**
足りないのは **「作っているもの」の軸**で、それは既に `STATE.md` にある。

```
縦の軸  プロジェクト   何を作っているか。**STATE.md から自動生成**
横の軸  記事           seeds / log / garden。**人が書く**
```

**片方を機械が持ち、片方を人が持つ。** これが分けられていなかったのが原因。

## ページ構成

```
/                    **ダッシュボード**（新）
                       いまの現在地・最近の動き・未決の pending・種の在庫

/projects/           **8件**（新。works を吸収）
/projects/[slug]/      STATE.md から自動生成 + 手書き本文があれば載せる

/toolbox/            **道具・Skill・サブエージェント・フック**（新）
                       inventory から自動生成。**「何がなんだか分からない」の解**

/log/                実録（既存のまま）
/garden/             わかったこと（既存のまま）
/seeds/              拾いもの（既存のまま）
```

### 捨てるもの

- **`/works/` を独立させること。** `/projects/` に統合する。
  手書き本文は `projects/[slug]` の本文として生かす
- **`/state/` の独立ページ。** トップに吸収する
- **道具を「記事」として書くこと。** 一覧は自動生成でよい

## 自分用と他人用

**分けるのはページではなく、同じページの中の順番。**

| | 上に来るもの |
|---|---|
| **自分** | いまの現在地 / 次の一手 / 未決 / 最近触ったもの |
| **他人** | 実録・わかったこと / 何を作っているか |

**トップは自分用に振り切る。** 他人が最初に見るのは `/log/` か `/projects/` で、
**そこへの導線をトップに置けばよい。**

## データの流れ

**生成器とページは必ずセットで置く**（`denki.html` が6日間止まった教訓）。

```
STATE.md            → /  と /projects/           既にリポジトリにある
inventory.py --md   → INVENTORY.md → /toolbox/    **リポジトリの外から書き出す**
seed_candidates.py  → 種の在庫（数だけ）→ /
```

**`INVENTORY.md` をリポジトリに commit する。** Skill も道具も
`~/.claude/` と `claude-handoffs` にあってサイトの外なので、
**書き出さないと描けない。** 書き出しを忘れると古い一覧が「動いて見える」。

→ **週次の棚卸し（木曜 01:15）で書き出して push する**のと同じ経路に乗せる。

## 公開の扱い

- **道具は載せる。** 記事の数字はスクリプトの出力なので、**裏付けが読めないと主張だけになる**
- **Skill は載せない。** 判断の中身が具体的すぎて、他人には文脈が要りすぎる
- `publish: false` は**サイト表示の制御でしかない**。機密はリポジトリに入れない

## やらないと決めたこと

- **全部を1つの分類に統一しようとしない。** プロジェクトと記事は寿命が違う
- **道具ページを手で書かない。** 22本あって増え続けるので、**必ず自動生成**
- **`seeds` を捨てない。** 在庫が無いのではなく、取り出す仕組みが無かっただけ

## 2026-07-31 に既に設計されていたこと

**この仕様を書いた後に、会話ログから見つかった。** 索引の設計は7月末に一度やっている
（`2026-07-31-チャット履歴の検索性を改善する索引システム`）。**取り込むべき点が2つある。**

### 索引は複数の親を持てる

```yaml
path: ["atelier", "grow-shelf"]    # 単一の親を強制しない
```

**描画時に木を組み立てる。** いまの目次は平坦なので、**この形にすると分類のやり直しが要らない。**
1つの会話が「電力」にも「栽培」にも属せる。

### トップ階層は手で固定する

**5〜6個に手で決め、自動クラスタリングはノードの内部だけに限定する。**

**上が動くと、毎回置き場所が変わって覚えられなくなる。**
`/`・`/projects/`・`/toolbox/`・`/log/`・`/garden/`・`/seeds/` の6つで、**これは既に満たしている。**

### そして Pagefind が既に全文検索を持っている

**索引は検索のためではなく俯瞰のため。** 探すのは Pagefind と grep の担当で、
**目次は「何があるかを知る」ためだけに要る。** 役割を混ぜない。
