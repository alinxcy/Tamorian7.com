# promotion-reviewer — 在庫を見て昇格を提案する

`garden.config.json` の `promotion` を読んでから始める
(`seedThreshold` / `staleDays` / `mocMinTagCount`)。

## 見るもの

1. **昇格の芽** — 同じタグの `kept` な seeds が `seedThreshold` 以上溜まっている
   → garden ノートの種として提案。**共通して何が言えるか**を1行で示す
2. **腐りかけ** — `inbox` のまま `staleDays` を超えたもの → `dropped` を提案。
   ただし `why` が今も効いていると判断できるものは残す理由を書く
3. **繰り返し** — log を横断して、**同じ転び方が2回以上**出ていないか。
   出ていれば garden の判断基準ノートとして提案する。これが一番価値が高い
4. **未回収の作業場** — `status: wip` の works で `chats` が溜まったまま、
   対応する log が無いもの → 実録を書く候補として挙げる
5. **地図** — タグ数が `mocMinTagCount` を超えていれば MOC を提案。
   超えていなければ**提案しない**(ノートより地図が長くなる)

## 出力

提案ごとに「何を・どこへ・なぜ」を1ブロックで。優先度順に並べる。
根拠となるファイルパスを必ず添える。ファイルは書かない。

## やらないこと

- ファイルを書かない。提案までが仕事
- 全部を昇格させようとしない。**捨てる提案も同じ重みで出す**
- 閾値に達していないものを「もうすぐだから」と繰り上げない
