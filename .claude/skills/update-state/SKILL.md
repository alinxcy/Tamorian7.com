# update-state — STATE.md を更新する

**セッションの長期維持は目的ではない。リポジトリが真実で、セッションはいつ切れてよい。**
だから重要なものは会話ではなくファイルに落とす。このスキルはその落とし込みを担う。

判定基準はひとつ。**新しいセッションを開いた人が、STATE.md だけを読んで
この2つに答えられるか。**

- Q1. 今何をすべき？
- Q2. **具体的にどのファイルのどこから着手する？直前に何を試してダメだった？**

Q2 に答えられないなら暗黙知が失われている。それは本文の「作業中の暗黙知」欄の失敗。

## 手順

### 1. 読む

- `garden.config.json` — 作業ブランチとパス。**値をこのファイルに書き写さない**
- `STATE.md` — 現状
- スキーマの正本は `scripts/state.mjs`。要約表は `CLAUDE.md`

### 2. フロントマターを更新する

**フィールドを勝手に増やさない・改名しない・型を変えない。** 描画側が壊れる。
変えたいときは提案して承認を取り、描画側とセットで直す。

- `last_updated` は**実時刻**に。`date +"%Y-%m-%dT%H:%M%:z"` の出力をそのまま使う。
  ここを更新し忘れると、人間が「止まっている」ことに気づけなくなる
- `progress` は 0.0–1.0。`status` は `active` / `paused` / `blocked` / `done`
- `next_action` は次の1手を一文で。`next_action_at` に着手する場所（ファイルパス等）
- 未確定は `pending[]` にだけ書く。**本文には書かない**（二重管理になる）

### 3. 本文を上書きする

常設は3つ。ここから増やさない。

1. 今やっていること / 優先順位
2. 次のアクション — 各項目に**「直前に何を試して、何がダメだったか」**を添える
3. 作業中の暗黙知 — どこまで調べたか、試してダメだった方法、ハマりどころ

**書かないもの:**

- 過去の経緯、撤回した方針、末尾の墓場セクション。
  スナップショットに履歴を溜めると下半分がノイズになり、AI が古い方針に引きずられる
- 生の時系列（「14:20 これがダメだった」）は `scratch/<YYYY-MM-DD>.md` の担当。
  **STATE.md の暗黙知欄は、そこから蒸留した「今も有効な結論」だけ**を置く

`current_focus` と本文の「今やっていること」を食い違わせない。
機械はこの一致を判定できないので、ここは書き手の責任。

### 4. 検証してから書く

```sh
node scripts/state.mjs     # STATE.md 単体
npm run check              # 他の機械判定も含めて
```

**手元に node が無い環境なら、push して CI に判定させる**
（`.github/workflows/check.yml` はブランチ指定が無く全ブランチで発火する）。
検証せずに「たぶん通る」で終わらせない。

### 5. コミットする

- 通常はそのままコミットしてよい
- **`public/` への変更が含まれる場合はコミットせず、人間に確認を取る。**
  `public/` は無加工で配信されるので、事故がそのまま公開になる

## 決定が確定したら DECISIONS.md へ

**「確定」とは人間が明示的に承認したものだけを指す。**
自分の判断で確定にしない。議論の途中・未検証の仮説・動作未確認のコードを
確定として書かない。迷ったら `pending[]` へ。

- **確定した瞬間に書く。** 会話の終わりまで溜めない
- DECISIONS.md は**追記のみ**。撤回したものは消さず「撤回済み・日付・理由」を追記
- 書くのは決定と**理由**。理由の無い決定は後から覆せない

STATE.md と DECISIONS.md を統合しない。寿命が違う（上書き vs 追記）。

## 他の AI から持ち込みがあったとき

ChatGPT / Gemini / Codex の話は人間が持ち込む。会話ログは保存しない。

- 受け取るのは**「決定・前提変更・TODO」と、その根拠となる原文の抜粋**だけ
- **要約**（圧縮と解釈が混ざる）ではなく**抽出**（原文のまま切り出す）
- 統合したら元は捨てる。リポジトリに会話を残さない
- 役割分担は固定しない。役割表より
  **「どのAIに何を渡して、結果どうだったか」の記録**のほうが後で効く
