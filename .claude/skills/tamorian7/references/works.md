# works — プロジェクトの三態

`src/content/works/<slug>.md`。テンプレート: `.claude/templates/work.md`

Works は**プロジェクトで切る縦串**。Garden(主題の横串)とは階層が違う。
garden / log に `project: <slug>` を書くと Works ページが自動集約ハブになる。

## status で本文の役割が入れ替わる

**`planned` — 構想**
なぜ作りたいか、解きたい問題。仕様書へのリンク。短くてよい。

**`wip` — 作業場**
書くのは3つだけ。**毎回上書きする。履歴を残さない。**机なので散らかったら片付ける。

- いま動いているところ
- いま詰まっているところ
- 次の一手

**`published` — 使い方**
主役が使い方に入れ替わる。何ができて、**何ができないか**。既知の限界。
作業場の記述はここで消す。

## 作業場 → log への吐き出し

作業中に溜まる「面白かったこと・転んだこと」は机の上に置いておけない。
溜まったら log に実録として切り出す。この経路があるので、完成時に作業場を消しても
**経緯は log に残る**。

## chats — 作業中だけ生きるリンク

`planned` / `wip` のときだけ表示し、**`published` にする際に削除する**。

```yaml
chats:
  - label: 仕様の壁打ち
    kind: claude
    url: https://claude.ai/chat/xxxxxxxx
  - label: 実装セッション
    kind: code
    session: 0a1b2c3d          # claude --resume <session>。同一マシンのみ
```

チャット URL は腐る(会話を消せば 404、しかも気づかない)。
**リンクの寿命と表示期間を一致させる**ことでこの問題を構造的に消す。

残っている `chats` は「まだ log に吐き出していない会話」のマーカー。
`published` へ移す作業が、リンクが腐る前の最後の締切になる。

**公開共有リンク(share)は使わない。** 会話の全文が出るため、途中の誤り・捨てた案・
貼った値がそのまま公開される。見せたい経緯は log に書く。
