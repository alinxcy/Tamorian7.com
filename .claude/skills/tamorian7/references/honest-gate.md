# honest-gate — 公開前に止める基準

**機械は止める、AI は問う。** 混ぜると、確実に落とせるものまで気分に左右される。

## (a) 機械判定 — CI でブロック(`npm run check`)

- frontmatter スキーマ違反(zod)
- 内部リンク切れ(`/garden/<slug>/` の実在確認)
- base パス忘れ(GitHub Pages 配信時の `/Tamorian7.com/` 欠落)
- 生の数式記法(`$...$`)が未レンダリングで残っている
- **`status: published` の works に `chats` が残っている** → warn
- 禁止語(`garden.config.json` の `honestGate.bannedPhrases`)→ warn。
  `allowWithReason` が有効なら、直後に理由コメントがあれば通す

## (b) AI 判定 — 書くときに問う(CI には入れない)

- **n=1 の観測を一般法則として書いていないか。**
  「〜する傾向がある」の根拠のサンプル数を確認する
- **確認していない既定値を、確認済みのように書いていないか**
- **数字に単位と測定条件があるか**
- **失敗・限界の記述があるか。** 無いなら「本当に何も転ばなかったか」と問う
- **断定の強さが根拠に見合っているか**

> これらは `log/2026-07-26.md` で実際に起きたミスから逆算した項目。
> 同記事には「比率の分母を表だけにしていたバグは極端なデータで初めて露見した」
> 「興奮して確定事実として書きかけたところを止めてもらえた」と書かれている。
> 止める役は実在の需要であり、そのときは人間がたまたま止めただけだった。

重い公開前レビューは会話でやらず、`honest-reviewer` サブエージェントに投げる。
