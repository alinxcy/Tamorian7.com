冷蔵庫にスマートプラグを付けて、20秒ごとに消費電力を記録している。
**霜取りヒーターは 115〜122W** で回るので、**58W の通常運転とはっきり分かれる。**
いつ来るかを追った。

## 1回目の仮説: 積算運転時間

最初の2点で、こう見えた。

```
           積算運転     経過時間
1回目→2回目  18.96h      25.12h
2回目→3回目  18.23h      24.69h
```

**積算運転が 18〜19時間で揃っている。** 1回目の 8.32h は
「電源投入から」なので途中から数えており、矛盾しない。

**「積算運転およそ19時間で霜取り」で予測を立てた。**
16時間後と計算し、実際は12:53。**約1時間の誤差で当たった。**

## 2回目の仮説: 24時間タイマー

3点目が出て、逆に見えた。

```
          積算運転   経過時間   その区間のデューティ
8/22      18.96h     25.12h        0.755
8/23      18.23h     24.69h        0.738
8/24      17.94h     24.82h        0.723
```

**経過時間はほぼ動かず、積算運転だけがデューティと一緒に落ちている。**

これは「時間で来るもの」を見ているときの見え方そのものである。
涼しくなってデューティが落ちたぶん、**固定の経過時間に含まれる運転時間が減っただけ。**

逆に積算運転がトリガなら、**トリガ値が 18.96 → 17.94 と5%も動く理由がない。**

しかも**霜取りの時刻が毎日45〜70分ずつ後ろへずれている**（10:15 → 11:22 → 12:04 → 12:53）。
**周期が24時間より少し長い**ことの直接の証拠になる。

**サイクル長（約70分）を考えると、「24時間経過後、次のサイクルの切れ目で入る」なら
間隔は 24.00〜25.18時間に散らばる。実測は全部その中にあった。**

## 5点そろえたら、支えが1つしかなかった

```
          積算運転   経過時間
8/22      18.96h     25.12h
8/23      18.23h     24.69h
8/24      17.94h     24.82h
8/25      17.95h     24.72h
8/26      17.86h     24.18h
          ばらつき 6.0%   ばらつき 3.8%
```

全体では経過時間の方が揃っている。**だが直近4回だけで見ると逆転する。**

```
直近4回   経過 24.18〜24.82（2.6%）   運転 17.86〜18.23（2.1%）
```

**両説を分けていたのは 8/22 の1区間だけだった。** そこだけデューティが 0.755 と高く、
積算運転が 18.96h と外れている。**それを除くと、両方とも同じくらい揃ってしまう。**

## なぜそうなるか

**デューティがこの5日間ほとんど動いていない**（0.723〜0.755）。

- 経過時間が一定 かつ デューティが一定 → **積算運転も一定に見える**
- **つまり、両説が同じ挙動を予測する条件下でしか測っていない**

**区別できる条件は「デューティが明確に落ちる日」**であり、それはまだ来ていない。
室温は 30〜33℃ で、まだ夏である。

## 追記(2026-08-27): その1点は、そもそも数えてはいけなかった

**唯一の支えだった 8/22 の区間には、外れる理由があった。**

プラグを挿したのは **8/20 20:16**。1回目の霜取りは **8/21 10:15** なので、
**最初の区間には設置直後の引き込みが丸ごと入っている。**
扉を開けて挿し替えた直後の冷蔵庫は、いつもより働く。

```
周期            運転      稼働率
8/21→8/22     18.96h    75.5%   ← 設置直後。他と比べられない
8/22→8/23     18.23h    73.8%
8/23→8/24     17.94h    72.3%
8/24→8/25     17.94h    72.6%
8/25→8/26     17.86h    73.9%
```

**「運転時間が5周期で減り続けている」と読んでいたが、違った。**
**2周期目以降は 72.3〜73.9% で平ら**で、傾きは1点目が作っていた。

つまり支えは1点でもなく、**ゼロ**だった。
**外れ値を見つけたら、外れた理由を先に探す。**
理由が「測り始めたばかりだから」なら、**それは反証ではなく、まだデータではない。**

## 手順にしたこと

- **仮説を採ったら、「何点で支えられているか」を数える。**
  点の数ではなく、**その仮説だけを支持している点の数**
- **1点しか無いなら「有力」と書かない。** 「まだ区別できていない」と書く
- **外れ値は、外れた理由を先に探す。**
  「測り始めたばかり」「設定を変えた直後」なら、**それは反証ではなくデータですらない**
- **区別できる条件が来ているかを先に確かめる。**
  条件が来ていないなら、点を増やしても分からない
- **当たった予測は、必ずしも情報を増やさない。**
  <!-- reason: 「必ずしも〜ない」の否定形。断定ではなく、断定を否定している側 -->
  両説が同じ予測をする区間で当てても、**どちらが正しいかは分からないまま**

**同じ計測から出たもう1本**: [測っているつもりで測れていない](/garden/resolution-floor/)。
そちらは分解能の床と、平均が山を消す話。

## 未確定

- **どちらが正しいか、まだ決まっていない。** n=5 だが、
  **区別できる区間は実質1つ**
- **判定は涼しくなるまで出ない。** タイマー説なら間隔は 24.7時間のまま運転時間だけ落ち、
  積算運転説なら間隔が伸びる。**秋まで待てば勝手に分かれる**
- **霜取りの継続時間が下げ止まったかも不明。** 29.1 → 27.0 → 25.3 → 27.0 → 22.9 → 24.6分と
  揺れている。「最初に溜まっていた霜を吐き切った」なら下げ止まるはずだが、**まだ言えない**
