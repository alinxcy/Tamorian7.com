電力会社のサイトから、自宅の**30分値を1年ぶん**（17,568コマ）落とした。
それまで「月180kWh前後」と推定して計算していたので、**実測に置き換わる。**

## 推定は22%高すぎた

```
推定   月180 kWh
実測   **月141 kWh**（1年 1,692.3 kWh / 366日）
```

段階制の判断（120kWh を超えるか）は変わらなかったが、**金額の見積もりは全部ずれていた。**

## 消費の77%がベースロード

```
時間帯別   最小 0.137 kW（09時台） 〜 最大 0.256 kW（22時台）
ベース    **0.149 kW** → 年1,306 kWh = **全体の77%**
```

そして**冷蔵庫は年401 kWh（45.8W）**。別途プラグで実測した値なので確かである。
**ベースロードの31%を冷蔵庫が占めている。**

**生活のピークは薄く、常時動いているものが支配している。**

## 「一日中平坦」は間違いだった

最初、366日を平均した時間帯プロファイルを見て「一日中ほぼ平坦」と書いた。

**平均が山を消していた。**

```
1日のピーク    中央値 0.60 kW / 上位10% 0.80 kW / 最大 1.20 kW
1日の振れ幅    中央値 0.40 kW（ピーク − 中央値）
```

**日内のピークは中央値の3倍ある。** エアコンを使う日と使わない日を平均すれば、山は消える。

月ごとに分けると、形がまるで違う。

```
        0時   3    6    9    12   15   18   21
2025-09  0.24 0.27 0.25 0.24 0.23 0.25 0.33 0.29   ← 夕方に山
2026-01  0.25 0.24 0.21 0.12 0.12 0.18 0.17 0.31   ← **2.6倍の振れ**
2026-05  0.13 0.14 0.13 0.10 0.13 0.15 0.15 0.15   ← これは本当に平坦
```

**平坦なのは春だけだった。**

## 分解能の床

```
30分値の中央値   0.1 kWh（= 0.20 kW）
75%tile も       0.1 kWh   ← **4分の3のコマが下限に張り付いている**
```

**メーターは 0.1 kWh 刻み。** 平均 0.19 kW の家では、**0.2 kW 未満の構造が見えない。**

最初「各日の最小30分値」でベースロードを出そうとしたら、**0.000 kW になった。**
量子化で潰れている。**静かな時間帯の平均で代用した。**

つまり **0.149 kW という値も、下限に押し付けられた結果**であり、
**実際はもっと低い可能性がある。**

そして**冷蔵庫（45.8W）は、この解像度では原理的に見えない。**
プラグを付けて別に測ったから分かっただけである。

## 間違いの形が同じだった

**この日、同じ形の間違いを2回した。**

- 冷蔵庫の消費電力を**時間ごとに束ねたら、偽の外れ値が出た**
  （同じ室温で73%と93%。約75分の運転周期に対するエイリアシングだった）
- 家の消費を**366日で平均したら、山が消えた**

**どちらも「束ねる単位が、現象の周期と噛み合っていない」。**
前者はサイクル単位に切り替えて解決し、後者は月ごとに分けて解決した。

同じ冷蔵庫の別の話は
[その仮説、何点で支えられているか](/garden/one-point-hypothesis/)。

## 手順にしたこと

- **平均を見る前に、分布を見る。** 中央値・上位10%・最大
- **最小値を使う前に、量子化の床に当たっていないか確かめる。**
  下限に張り付いている割合を数える
- **束ねる単位を、現象の周期と揃える。** 揃っていないと偽の構造が出る
- **推定値のまま計算を積み上げない。** 実測が1枚入るだけで22%動く

## 未確定

- **ベースロードの真の値が分からない。** 0.149 kW は分解能の床に押されている。
  **分ける方法はプラグを増やすことだが、常時負荷が何個あるかも分かっていない**
- **冷蔵庫以外の常時負荷が何なのか。** ベースロードの残り69%（年900 kWh）が
  何に使われているか、**まだ切り分けていない**
