会話ログから索引を作る仕事を、安いモデル（Sakana Fugu の base）に外注していた。
出来が悪かったので、**上位モデルに上げるか、Claude でやるかを考えた。**

**測ってみたら、どちらも不要だった。**

## 何が起きていたか

索引の目的は**語彙を残すこと**にある。あとで `grep` して原文に当たるための取っ掛かりなので、
クラス名・例外名・ファイル名がそのまま残っていないと機能しない。

残っていなかった。

```
原文にあった識別子のうち、索引に残っていた割合   6.2%
```

**93.8% が消えていた。そして数週間、誰も気づいていなかった。**
索引は「ちゃんとした索引」に見えていて、エラーも出ない。

## 3つ比べた

同じ会話3本（12KB / 70KB / 144KB）に、同じ仕事をさせた。

| 原文 | Fugu（元のまま） | Claude のサブエージェント | **Fugu（プロンプトを直した）** |
|---|---|---|---|
| 12 KB | 6.2% | 92.6% | **100.0%** |
| 70 KB | 9.9% | 73.7% | **97.5%** |
| 144 KB | 6.7% | 34.6% | **86.7%** |

**プロンプトを直した Fugu が、3本とも Claude を上回った。**

大きい原文で Claude が 34.6% まで落ちるのは、**全体が見えるぶん「まとめた方がいい」と
判断して細部を捨てる**からだと思われる。安いモデルは塊ごとに機械的に舐めるので、
**取りこぼしにくい。**

## 直したのは2行

```diff
- 「項目は3〜7個」
+ 「この塊に出てくる話題をすべて」

+ 「固有名詞・型番・関数名・クラス名・ファイル名は原文のまま使え。言い換えるな」
```

**上限の縛りが薄さの原因で、固有名詞の指示が無いことが欠落の原因だった。**
どちらもモデルとは関係がない。

## 効いたのはむしろ3つ目の変更

**「残せ」と頼むのをやめて、機械が拾ったものを渡した。**

```
識別子を正規表現で全部抜く（無料・毎回同じ・取りこぼしゼロ）
        ↓
原文と一緒に「この範囲に出てくる識別子」として添える
```

**頼むと相手の裁量に依存する。渡すと依存しない。**

同じ形は同じ日にもう一度出た。候補200件を「これは他人の成果か、ただの語か」判定させたとき、
`YouTube` や `PowerPoint` が「製品＝種」として返ってきた。
**指示が「他人の成果か」だけで、「種にする意味があるか」を言っていなかった。**
**モデルの誤りではなく、指示の不足。**

## そして行き過ぎた

6.2% を直そうとして上限を外したら、**索引が原文より大きくなった。**
12,143字の会話に対して索引が 12,500字。**索引ではなく写しである。**

**測れる指標を作った瞬間、それを最大化しに行く。**

上限だけ・下限だけの指標は壊れる。範囲で持つしかない。
さらに**小さい入力では割合の上限が効かない**（5,873字の会話で 38% は、
絶対値では 2,200字＝十分小さい）ので、**絶対値の下限も要る。**

いまの門はこうしている。**外れたら作り直す。**

```
語彙の残存率  35〜92%    低すぎ=薄い / 高すぎ=写しになっている
索引の大きさ  原文の20%まで（ただし3,000字までは不問）
```

## 手順にしたこと

- **モデルを上げる前に、プロンプトの1行を疑う**
- **「残してくれ」と頼めるものは、たいてい機械で抜いて渡せる**
- **外注には機械で測れる品質指標を1つ以上付ける。** 範囲で持つ
- **指標を1つだけ最大化しない**

## 未確定

- **どこまでが「プロンプトで埋まる差」なのか。** 今回は3本で逆転したが、
  **もっと判断が要る仕事では違うかもしれない**。n=3
- **ローカルの小さいモデルでも同じ結果になるか。** 識別子の抽出を機械に移した結果、
  LLM の担当は「まとまりを見つけて1行で言う」だけになった。**7B〜14B で届く見込みはあるが未検証**
