充電制御の Phase 3 配備をやった。制御スクリプト群を自宅PCから Pi へ移し、電気料金——JEPX 価格——の CSV も Pi が自前で取得する形に変えた。「Pi へ移す」はファイルを配る作業だと思っていた。送るものをリストにして、送って、動かす。実際、配り忘れたファイルもあった。ただ、この日3回転んだうち、ファイルの配り忘れは1回でしかない。3回とも同じ形だったのに、その形に気づいたのは3回目の後だった。

最初の転びは、配ったスクリプトの側にあった。charge_cheap / charge_plan / soc / cheap_now が `~/atelier-lab/...` という自宅PCのパスを決め打ちしていた。Pi にそのパスは無い。

## 4日間動き続けた、古いままの操作盤

次はファイルの側。23時49分に記録した。charge_cheap.py / soc.py / charge_plan.py / charge_mode.py / jepx.py は送ったのに、操作盤の panel.py だけ配備リストに入れ忘れていた。操作盤は 8/30 の古い版——充電操作 charge_control が無い——のまま4日間動き続け、今夜、人に「ボタンが無い」と指摘されるまで誰も気づかなかった。systemd は古い版でも `active (running)` と表示する。プロセスが動いている＝最新、ではない。

ついでに panel.service の unit に環境変数 CHARGE_MODE_STATE / CHARGE_PLAN_PATH が無いことも見つけた。既定値で動くとはいえ、同じ機械を見る charge-cheap.service 側には明示してある。同じ機械を見る2つのサービスは、環境変数の書き方も揃えるべきだった。panel.py を配り直し、unit に環境変数を足して再起動。/api/state の charge_control が埋まることを確認した。

## 直した直後に、また同じ形で

23時54分に記録した3回目。直した直後、今度は価格表示が null のまま。panel.py が CSV_PATH に `~/spot_summary_2026.csv` を決め打ちしていて、コメントには「自宅から配ってもらう」とある。今日まさに Pi 自前取得へ変えたのに、古い置き場所の前提がここだけ残っていた。新しい置き場所は `~/jepx/data/spot_summary_2026.csv`。

対処は、環境変数 JEPX_CSV で差せるようにし、未指定なら新しい場所を優先、無ければ旧来のホーム直下を見る順にした。移行期の保険。締めのコミットでは WAKE_DIR / JEPX_DIR / JEPX_CSV / JEPX_DATA / CHARGE_MODE_STATE / CHARGE_PLAN_PATH を全部環境変数で差せるようにした。既定値は従来どおりなので自宅PC側は変わらない。wake と jepx のテスト59件で確認した。

## 移設とは、前提を洗い直す作業だった

同じ日に3回、同じ形で転んだ。決め打ちのパス、配り忘れ、また決め打ちのパス。共通するのは、各ファイルが抱えている「他のものがどこにあるか」という前提を、配るものと一緒に数えていなかったこと。ファイルはリストにすれば数えられるが、前提は各ファイルの中に散らばって書いてある。次の移設では、配備前に決め打ちパスを grep で一括して洗う。確認するのは「動いているものを送った」ではなく「動くために要るもの全部を送った」。

配るのは一瞬で、洗い直すのは面倒だ。ただ、面倒な方を飛ばすと同じ形で3回転ぶ。4回目の分の面倒は、もう前払いしてあると思いたい。
