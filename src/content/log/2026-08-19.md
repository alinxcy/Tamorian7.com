**カードが遊んでいた、というのが本当の動機。** チューナーレステレビを買ったから、は後付けで、
5,000円の USB チューナーを買えば済む話に半日かけた理由はそこにしかない。

PX-Q3PE(無印) を Ubuntu 24.04 / kernel 7.0.0-28 で動かす。
上物(Mirakurun + EPGStation)は別途 Antigravity が並行して作っている。

## 実測でわかったこと

- **世代の判定は `lsusb` で付く。** PE4/PE5 は PCIe から電源だけ取ってデータは内蔵 USB で
  流すので、**必ず `lsusb` に出る。出なければ無印。**
  <!-- reason: 統計ではなく回路構成からの帰結。USB でデータを流す以上、列挙されないことはない -->
  そして [px4_drv](https://github.com/nns779/px4_drv) の `driver/` は
  `px4_usb.c` / `itedtv_bus.c` の **USB 専用で、PCIe のコードが1行も無い。**
  対応一覧に無印が無いのは、書き忘れではなく設計
- 使うのは [knight-rider/ptx](https://github.com/knight-rider/ptx) の chardev 版。
  `pxq3pe_pci.c` の PCI ID テーブルが `{0x188B, 0x5220, 0x0B06, 0x0002}` で、
  `lspci` の **vendor / device / subsystem 4項目すべてに一致**した
- **デバイスノードは8本、地上波と衛星が交互。** `/dev/pxq3pe_drv00t` 〜 `07s` で、
  **偶数が t(地上波)、奇数が s(BS/CS)。** 「0〜3 が地上波」ではない。
  `device_create` の書式 `"%s%x%x%c" ... i & 1 ? 's':'t'` からそのまま読める
- **I2C コントローラの詰まりは `FIFO_STAT` の下位5ビットで見える。**
  正常が `0x10`、詰まると `0x0a` / `0x0b`
- **`PXQ3PE_I2C_SW_CTL (0x948)` に全ビットを立てて元の値に戻すと、詰まりが解ける。**
  `fifo_stat` が `0x800a` → `0x8010` に戻り、**コールドブートが要らなくなった**
- **PCI ファンクションリセット(`pm` / `bus`)は効かない。全レジスタが1ビットも変わらない。**
  「Q3PE は温かい再起動でリセットされない」という既知の癖の正体はこれで、
  回避策の不足ではなく**ハードがリセットを無視している**
- 電気的には健全。`LnkSta` は **x1 @ 2.5GT/s**、エラーカウンタ 0。
  **ブラケットを紛失していてカードは自重のみで載っている**が、そこは問題になっていない
- **内蔵の B-CAS リーダーは使えない。** ドライバ側が `return 0` のスタブで、
  USB のカードリーダーが別途要る

## 実装で刺さった罠

1. **`make` が何も作らない。** `obj-m` が空だった。
   Makefile が bash 構文(`$(shell eval source dkms.conf)` と配列展開)なのに、
   **make の `$(shell)` は `/bin/sh` = dash。** `SHELL=/bin/bash` で解決
2. **`media/dvb_math.h` が headers パッケージに無い。**
   ただし `intlog10` は `Module.symvers` に**今もエクスポートされている**ので、
   宣言だけ自前で補えば通る
3. **kernel API がひととおり変わっている。**
   `i2c_driver.probe` の第2引数削除(6.3)、`remove` の `int` → `void`(6.1)、
   `strlcpy` 削除(6.8) → `strscpy`、`pci_set_dma_mask` 廃止(5.18) → `dma_set_mask`
4. **`objtool: unannotated intra-function call`。**
   リポジトリ独自の `-O3 -Os` が原因で、カーネル既定に戻したら消えた
5. **`pxq3pe_i2c_xfer` が `return i` を返していた。ここが半日の本体。**
   ```c
   for (i = 0; i < sz && ret; i++, msg++) { ... }
   return i;   /* 失敗しても i は加算されてから抜ける */
   ```
   1メッセージの書き込みは `== 1` で成否を見るので、**失敗しても成功に見えていた。**
   2メッセージの読み出しだけが `== 2` で正しく検出していた。
   `return ret ? i : -EIO` に直したら **probe が落ちるようになった。**
   直したのではなく、**ずっと失敗していたものが見えるようになっただけ**
6. **詰まりを掃除する処理の前に、詰まりを弾くガードがあった。**
   ```c
   if ((readl(FIFO_STAT) & 0x1F) != 0x10 || ...) return false;
   writel(0, CTL_STAT);   /* ← 掃除はこの後 */
   ```
   **一度汚れると、掃除する処理に到達できない。**
7. **自分のミス: 掃引の結論を先に出した。** 物理チャンネル 13〜52 を掃引して全滅し、
   「電波が来ていない」と結論した。だが 5 と 6 のせいで、
   **最初の1回が失敗した時点で残り39チャンネルは必ず失敗する運命だった。**
   <!-- reason: 「詰まりを掃除する処理にガードで到達できない」ことからの論理的帰結。実測の一般化ではない -->
   **一度失敗すると以降が無意味になる構造**を確認せずに40回回していた。
   掃引が示していたのは1件目だけ
8. **自分のミス: `dmesg -C` してから probe を撮り直そうとしたが、probe はもう終わっていた。**
   ログを消す前に、何がいつ起きるかを考えるべきだった
9. **自分のミス: 上物側の申し送りを、相手の成果物を一度も見ずに書いた。**
   pcscd をホストで動かせと書いたが、`chinachu/mirakurun` はコンテナ内で動かす設計。
   デバイス名も「未確定」と書いたまま渡した

### 効かなかったもの

記録しておく価値があるので残す。

- `writel(0, CTL_STAT)` をガードの前に移動 → `ABORT after reset`。**値が動かない**
- `hw_init` 冒頭の設定書き込み(`0x904`/`0x900`/`0x890`)を手で再現 → 動かない
- `FIFO_DATA` を16回読む → `0x0a` のまま、データも常に 0。
  **吸い出せる種類の詰まりではない。** これは
  「FIFO のカウンタなら読んだら減るのでは」という指摘から試したもので、外れた。
  ただし**測定自体を疑う視点は正しく、こちらは peek が破壊的でないかを先に確かめるべきだった**

## 未確定のまま残したこと

- **`SW_CTL` のどのビットがリセットなのか、同定できていない。**
  全ビット立てて戻すという乱暴な手のまま。`orig|1` だけでは効かなかったので
  **bit0 ではない**ことだけが分かっている。n=1
- **そもそもなぜ FIFO が汚れるのかが分かっていない。**
  probe の途中で `0x10` → `0x0a` に変わる。末尾の `tc90522_lnb()` が
  最初の「読み出し」を発行するので疑っているが、
  **dyndbg を probe より前に有効化できておらず、その瞬間を撮れていない。**
  **対症療法である自覚はある**
- **受信そのものが確認できていない。** `Recorded 3sec` までは通ったが、
  修正後の(信頼できる)掃引でも 13〜52ch すべて C/N が `nan`。BS も TSID が読めない。
  ただし**ケースが干渉してカードの片方の端子にしかケーブルが挿さらない**ので、
  **アンテナ側の問題と切り分けられていない。**
  短いのではなく**細い**ケーブル(2.5C・外径4mm・L型)を調達してから測り直す
