この日の夕方には、小型モデルを並べて総当たりで採点するリーグ戦の用意ができていた。gemma4、qwen3、granite——どれが「種」を一番うまく拾えるか。けれど、その前にもう答えの一部は出ていた。同じ聞き方での2モデルの差は、0.5〜4点ほど。同じモデルで聞き方を替えたときの差は、17〜21点。

「種」というのは、会話ログに出てきた固有名のうち、あとで調べる価値のある、他人の作った道具・モデル・形式などのこと。それをローカル LLM に選別させたい。先生役は、外部の判定器 Fugu の過去の判定だ。

## 採点係も、もとから揺れていた

05:03 の時点で、Fugu の過去ログを数えていた。呼び出し401回のうち246回は利用上限のエラー、2回は読めない応答。残った判定は8,732件、544語、20日分。3日以上判定された462語のうち53語で、Fugu の判定は割れていた。ぶれ率にして11.47%。採点する側の物差しが、最初からまっすぐではなかった。

## 詰まったのは判断ではなく、答えの形だった

朝の安い枠で gemma4 と granite を回すと、二つとも1チャンク目でつまずいた。format=json とだけ指定すると、gemma4 は60語渡しても1件しか返してこなかった。結果の配列を包む形を JSON スキーマで書き直すと、同じ1チャンク目で gemma4 は 60/60 を37秒で返した。granite も 57/60、余計な語23で76秒。少なくとも gemma4 について言えば、止まっていたのは判断の中身より手前、答えの骨組みの方だった。

## 同じ二つのモデルで、聞き方だけで17点以上動いた

14時台、採点の土台を決めた。Fugu が10回以上判定し、9割そろった428語を「銀」と呼ぶ。この銀で本番の聞き方（v1）を採点すると、gemma4 は 62.4%、qwen3:8b は 62.9%。モデル間の差は0.5点しかない。

定義を書き直し、問題集に無い語で例を足した聞き方（v2）に変えて同じ428語を採点すると、gemma4 は 79.2%、qwen3:8b は 83.4% と 80.8%（同じ条件で2回）。聞き方を替えただけで、gemma4 で約17点、qwen3 で18〜21点動いた。v2 どうしでも2モデルの差は1.6〜4.2点で、聞き方の差には遠く及ばない。しかも qwen3 は v2 の同じ条件の2回で2.6点ぶれている。1モデル・2回だけの値だが、v1 の0.5点という差は、この程度のぶれと区別できないかもしれない。

間違いの中身を見ると、qwen3 の v2 は種にしすぎが60語——OpenAI や JetBrains のような会社名、CMakeLists.txt や *.gguf のようなファイル名、V2.1 や FY2026 のような版番号・年度。取りこぼしは18語で、Q4_K_M のような量子化の形式、NoLiMa のようなベンチマーク名、MinGW-w64 のような道具。gemma4 は逆に、取りこぼしが2語しかない代わりに、種にしすぎが85語。二つのモデルは同じ間違い方をしていない。

ここから v3 で足すルールを書き出した。会社名は種ではないがその会社の製品は種、拡張子があればファイル名、版番号や年度は種ではない、自分で名付けた内部の名前は種ではない、誰かが定めた形式名やベンチマーク名は種。

17:34、リーグ戦を組んだ。小型4本を足し、全モデル×v1/v2 を銀428語で採点する。10/1 12:00 の安い枠に1回だけ流す。PC に届かない、モデルが無い、そのときは回さない。0% の行を台帳に残したくないからだ。

ただしリーグ戦の結果も、v3 がどれだけ効くのかも、9/30 の時点ではまだ無い。銀そのものが Fugu の多数決である以上、測っているのは正解率ではなく Fugu との一致率で、その当の Fugu が11%ぶれる。モデルを比べる土台を作ろうとして、比べる前に動くものの方が大きいのを見つけてしまった格好だ。
