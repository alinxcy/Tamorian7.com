### 「実行しました」が3回空振りしていた

設定を直しても何も変わらない、が3回続いた。**docker が権限で弾かれていた。**
**Claude Code の `!` は同じユーザーで走るので、本人が叩いても同じく permission denied。**
→ docker を伴う作業は本人が普通のターミナルで `sudo docker`。

**気づけたのは `ps -eo cmd | grep ^recpt1` で動いている現物を見たから。**
設定ファイルにもコンテナのログにも出ない。**動いているコマンドラインだけが嘘をつかなかった。**

### not found の真犯人は検索パスだった

ホストの `libarib25.so.0` をコンテナへマウントしたが `ldd` が not found。
最初は「Ubuntu(2.39) と Debian12(2.36) で libc が違う」を疑ったが、
**`objdump -T` で見たら要求は最大 GLIBC_2.34。版の問題ではなかった。**

真犯人は **`/usr/local/lib` が `ld.so.cache` に載っていないこと**。
マウントで後から置いたファイルは索引に無いので、存在しても見つからない。
→ **`LD_LIBRARY_PATH=/usr/local/lib` の1行で解決。**

### wake の条件からFuguを外した

**8/31 に指摘した「仕事があるかを見ていない」は既に直っていた。**
`llm_jobs()` がキューを見るようになっていて、`kind=claude` は
「無人では走らないので数に入れない」と意図的に除外されていた。**仕組みは正しかった。**
食わせる仕事が無かっただけ。

変更は1点: **`decide()` から Fugu の条件を外した**(本人指示)。
Fugu の生死とローカルの仕事の有無は無関係。**見るべきはキューだけ。**

**わざと落として確かめた。** テストジョブを積んだのに「仕事が無い」のまま。
原因は**表記ゆれ**で、`queue.py` の内部は `llm-pc`(ハイフン)が正。
`llm_pc`(アンダースコア)で積んだ私が間違えていた。積み直して:

    仕事0件 → "ローカルにやらせる仕事が無い"
    仕事1件・高い時間 → "**power is expensive**（仕事 1件）"   ← いまここ
    仕事1件・安い時間 → "power is cheap / **仕事 1件**"       ← 強制的に通して確認

**明日 01:30〜02:30 が 10.56円/kWh。** テストジョブ(nvidia-smi)を積んだまま残したので、
そこで自動的に起きるはず。**LLM PC のアイドル電力の実測が、これで取れる。**
