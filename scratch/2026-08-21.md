## 2026-08-21

丸一日、冷蔵庫を測っていた日。合間に Tailscale / CGNAT の調査と、ペロブスカイトの話。

### 家のネットは CGNAT だった(経路で確認)

- Tailscale を張るならクライアントは**2台だけ**でよい(アトリエのラズパイと家のPC)。
  プラグや ESP32 には要らない。**`--advertise-routes` で LAN ごと通す**
- バッファローの家庭用は Tailscale 非対応。ファームが閉じていてパッケージを足せない。
  対応しているのは GL.iNet / OpenWrt / Synology あたり
- **`tracepath` で二重 NAT が見えた。** これが決定的
  ```
  1: _gateway            (100.64.1.1)
  2: 10.128.0.1                        ← ★ここがプライベート
  3: ...megaegg.ne.jp                  ← ここから公開網
  ```
- **IPv6 は来ていない**(グローバルアドレス0個、経路も無し)。抜け道が無い
- `pmtu 1492` = **PPPoE**。日本の「夜だけ遅い」の典型的な条件が揃っている。
  IPv6 IPoE が使えれば網終端装置を迂回できるので、**VPN と無関係に速くなる可能性**
- **家の LAN が `100.64.1.0/24`** で、これは Tailscale が自分のアドレスに使う範囲。
  **Tailscale を入れる前に `192.168.x.x` へ変えること**

### 冷蔵庫: 霜取りを見つけた

- 10時台に消費が倍になった。**56.4W → 116.9W に一段で上がって28分一定**、
  その後 **4分間の完全な0W**、そこから 82.9W で再始動して30分かけて 64W へ減衰
- 4分のゼロが決め手。**溶けた水が落ちきるのを待つ時間**で、霜取りの署名そのもの
- **霜は庫内ではなく、奥に隠れた蒸発器のフィンに付く**(間冷式)。
  「安い冷凍庫にできる大きな氷」は直冷式で、あれは冷却器が庫内の壁そのもの
- **累積コンプレッサ運転 8.32h / 経過 11.36h** で1回目が来た。8時間タイマーとみて自然
- ヒーターの熱は庫内に入るので**二度払い**になる。57Wh 溶かすと、汲み出しに +20Wh 程度
- 副作用: **8時間おきに表面が溶けて再凍結**している。アイスがシャリシャリになる理由

### 停止時間が主指標だと分かった

外気温との相関を指標ごとに比べたら、はっきり差が出た(n=12)。

```
1/停止時間  r=+0.91   ← 最良
停止時間    r=-0.90
デューティ  r=+0.80
運転時間    r=+0.42   ← 弱い
```

**停止中はコンプレッサが無関係**で、庫内はただ部屋から熱を貰って一定幅だけ温まる。
つまり `1/停止時間 ∝ 熱侵入速度 ∝ (室温 − 庫内温度)` が一次式になる。
**予測どおり逆数が最も直線的だった。**

- 外挿してゼロになる点が **2.1℃**。冷蔵室の設定温度と符合する。モデルが破綻していない傍証
- **これは断熱の計測器になる。** ドアパッキンが劣化したら跳ね上がる
- 運転中Wは**別の物理**(凝縮圧力)を見ている。約 1W/℃。
  **2軸あると切り分けができる**: 停止時間だけ動けばドア、運転Wだけ動けば凝縮器

### 踏んだ罠と、自分のミス

- **`current_power` はミリワットだった。** 生値を W として記録し、
  ログに `w: 2829` と出て「2.8kW!?」と読み違えかけた。
  **気づけたのは `wh_today` が動かなかったから。** 数字が2つあると片方が嘘をつけない
- **1時間で区切ったら偽の外れ値が出た。** 同じ32.4℃で 73% と 93%。
  周期(約75分)と枠が干渉していただけで、物理ではなかった。**サイクル単位に変更**
- **停止時間を直線で外挿して「庫内温度 55.3℃」と表示した。** それは
  「停止時間がゼロになる温度」で別物。**庫内温度は逆数がゼロになる点**
- **サンプリング60秒では停止時間の分解能が足りなかった。** 15.1 / 17.1 / 18.1 と
  1分刻みに量子化され、17分に対して6%。**20秒に上げた**
- **原因の推測を2回続けて外した。** 「帰宅で運転が伸びた」→ 実際は14:50から伸びていた。
  「室温が外気温に遅れている」→ ずらすほど相関が下がった。**そこで推測を止めた**
- **`--sim` と `--dry-run` が実 state を汚していた。** 1日を早回しすると
  「今日は充電済み」フラグが立ち、その日の本番が動かなくなる
- **ダッシュボードが自動更新されていなかった。** 10分ごとに HTML を作り直しては
  いたが、ブラウザは読み直さない。**「ダッシュボード」の名に値しなかった**

### ペロブスカイトと、小さな工場

- **栽培棚の本当の動機は「小さな工場を作りたい」だった。** 野菜工場はその候補の一つ
- ペロブスカイトは**個人向けにはまだ売っていない**。積水化学 SOLAFIL が
  2026-03 に事業開始したが企業・自治体向け。家庭の屋根は2030年代半ば以降
- **自作は「カーボン電極・HTLなし」構成なら成立する。** 蒸着も spiro も要らない
- 材料費(Ossila、実価格): **FTOガラス $390/100枚、前駆体インク $300/160基板ぶん**。
  **1セルあたり1,000円を切るが、最小ロットが10万円単位**
- **DMF が本当の関門。** 皮膚から吸収され、ニトリル手袋を透過する。局所排気が前提。
  日本の試薬メーカーは個人に売らないことが多いが、**Ossila の前駆体インクは
  溶媒に溶かした状態で届く**ので調達問題を回避できる
- **屋内光発電が狙い目。** 低効率でよく、紫外線も雨も無いので劣化が緩い。
  そして**自分のセンサ網が内部顧客になる**
- **「使えるもの」にする最大の関門は封止。** 効率を上げるより難しく、重要
- 面積が有限なので**ラインではなくセル生産(1台が全工程)**。
  工程は待ち時間が支配的(焼成30分×2)なので**腕は暇で、律速はオーブン容量**。
  ロボットアームより**改造3Dプリンタかロータリーテーブル**の方が向く
- **腕が本当に価値を出すのは貧溶媒の滴下タイミング1箇所。** 歩留まりを直接支配する
- **タクトタイムの楽しみはスケジューラに移せる。** 物理ラインを組まなくても取れる

### 深夜まで持ち越した件（日付をまたいだので追記）

- 22:03 から**運転が止まらない**。00:24 時点で **141分連続**。
  昨夜は同じ 26℃ で 37〜47分だったので、気温では説明できない
- 運転中Wが **55.6 → 59.3 → 58.3** と**わずかに上がって頭打ち**
- **着霜なら電力は下がるはず**。蒸発器が霜で覆われれば熱を吸えず、
  吸入圧力が落ちて流量が減る。**上がっているのは汲み出す熱が増えている**方
- → **ドアが閉まりきっていない**が第一候補。半開きなら対流で熱が入り続け、
  このコンプレッサの能力(80〜100W)を軽く超えて、設定温度に永久に届かない
- **霜取りが2回とも予測を外した説明にもなる。** 多くの機種は運転が終わった
  タイミングで霜取りに入るので、**止まらなければ入る隙がない**
- 本人にドアの確認を依頼した。閉め直して30分で止まれば確定。
  止まらなければ電力が下がっていくかを見る（着霜側の署名）
- **00:27 追記。ドアの開けっ放しではなかった**(本人確認)。ぬるい水を入れた、
  中身を探して開けていた、など**通常使用の熱**。方向は合っていたが機構が違った
  - 1L を 25℃→5℃ で **23Wh**。コンプレッサの仕事に直すと**約16分の運転**に相当
- **144分連続、まだ止まらない。** 57.7W で横ばい(外気温26.0℃)
  - 昨夜の同条件は 53〜55W なので **3〜4W 高い**。室温が外気温より高い可能性
- ドア開けの検出は**できなかった**。停止中の非ゼロは 22:03:07 の 0.926W が1点だけで、
  これは起動過渡の可能性が高い。**運転中は58Wに埋もれるので原理的に見えない**
- **測定上の教訓: 在宅の夕方〜夜は交絡だらけ。** きれいなベースラインは
  **就寝中と留守中**しかない。解析はそこを主に使うべき
- 判断の目安: 夜間・室温26℃で**4時間以上止まらないなら能力不足**を疑う。
  そのとき**運転Wが時間とともに下がっていれば着霜**、横ばいなら負荷側

### Fugu を投げてみて、損した（01時頃）
