## 2026-09-19 CANダンプ解析（京都往復 5時間49分、4259万フレーム）
- Drive から 3.29GB の CSV を取得（581Mbps、数分）→ duckdb で **ID別 parquet に変換 32秒、379MB**（メモリ最大968MB）
- 119 ID。既知の7個以外に大量にある。**0xAA は 0x215 と同じ構造の4輪速（別系統）**
- **MG2 を車速との相関で総当たり**（119ID × 28窓）→ 0x24A byte2-3(符号付きBE) が本命。
  他の候補（0xB4/0x217/0x215/0xAA）は傾き ≈ 99.99 = 車速のコピーだが、**0x24A だけ傾き 72.36 で負値も取る**
- **MG1 は「探さずに計算」**（本人の助言）。遊星拘束 `Ng = a*Ne + b*Nmg2` の形で2変数回帰を全窓に当てる
  → **0x24A byte0-1(符号付きBE)、R²=0.99985、a=3.5968、b=-0.98564**
- 物理と一致: **ρ = 1/(a-1) = 0.3849**（THS-II 設計値 30/78 = 0.3846）、MG2 減速比 k = 2.636
- **拘束式の残差 平均10rpm / p95 34rpm**（MG1 のばらつき ±2185rpm に対し 0.5%未満）
- 運転場面: 停車=全部0 / EV走行(43km/h) Ne=0・Ng=-3099 / 巡航(89km/h) Ne=1391・Ng=-1343 / 加速 Ne=3288・**Ng=+5019 に反転**
- 副産物: **0x202 byte0-1 は「エンジン回転数×4」と確定**（a=4.0000, R²=1.00000）。昨日の ×0.25 論争はこれで決着
- 昨日「HV電圧候補」としていた 0x24A byte4-5 は別物。**同じIDの中に MG1/MG2 が並んでいた**
- **外注3者を並行**（本人指示）: Fugu=**週の枠切れ**(9/21まで) / アングラさん=HV探索（走査を起動して報告だけ返し、成果物なし＝呼び方が悪かった） / コデちゃん=トルク探索（182k tok、15.8KBの報告書）
- **コデちゃんの成果（確定なしと正直に報告した上で有力候補）**:
  - **0x24B byte2-3 = MG1トルク候補 / byte4-5 = MG2トルク候補**。どちらも **0x8000 がゼロ点のオフセット表現**
    （普通の符号付き16bitとして読んで平均してはいけない。昨日の私の「中央値を引く」処理は形としては合っていた）
  - 高負荷EV（5kW超）で **符号一致率 100%**（加速）/ 97.7%（減速）。ただし 1count=1Nm 仮定の比は 0.68〜1.37 でばらつく
  - **原因は私の基準が粗いこと**を指摘された: `p_mech=1500*a*v` に**転がり・空気・勾配・摩擦ブレーキが無い**
- 本人の判断: **比のばらつきで係数を決めるのは危険。トルクは候補のまま置く。** 勾配 > 空気抵抗。
  エンジン始動中は MG1 が別の仕事をしているので駆動と比べるとずれる
- **摩擦ブレーキをビット単位で探索**（全119ID × 64ビット）。減速中に立ち加速中に寝るビットを対比で抽出:
  | ID/bit | 減速中 | 常時 | 立時のa | 見立て |
  | 0x24B k6_3 | 92.5% | 15.5% | -0.288G | ブレーキ操作（本命） |
  | 0x127 k3_0-2 | 86.7% | 14.9% | -0.284G | 同（別系統） |
  | 0x328 k0_5 | 94.6% | 47.7% | -0.093G | アクセルオフ |
  | 0x165 k0_7 / 0x224 k0_5 / 0x248 k3_1 | 72-75% | 4% | **-0.74〜-0.78G** | 強い制動 |
  - **常時立つ割合と減速度の強さがきれいに対応**（47%→弱 / 15%→中 / 4%→強）。段階が分かれている
  - 昨日「意味不明」だった **0x248 に意味が付いた**（強い制動のフラグ）

- **走査のバグ3連発（全部私）**:

  3. **duckdb は日本語の列名を引用符で囲む**。素の split では鍵が一致せず、結果が全部捨てられていた
