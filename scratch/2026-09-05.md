### 朝 — 反応的モードが本番機で死んでいた（atelier-lab 81c20b5, 10:26）

- 本人が操作盤を見て質問:「SOC 30%・価格 29.0円/kWh(48コマ中8番目に安い)なのに、なぜ充電していない?」
- 残量30〜50%は「反応的モード」の担当。安い枠が来たら入る段
- 前日 9/4 に、この反応的モードの判定を作り直したばかり（9/4-wake.md）。
  「閾値を割った最初の枠に飛びつく」→「今日の残りコマの中で最安のときだけ入る」(is_remaining_min)。
  テスト32件通過、わざと旧ロジックに戻して新テストが落ちるのも確認済み
- 原因は判定ロジックではなくパス。9/3 の Phase 3 移行で埋め込まれた1行:
  `CHEAP = os.path.join(JEPX_DIR, "cheap_now.py")`
- home PC では cheap_now.py は JEPX_DIR 直下。Pi では JEPX_DIR はデータ置き場だけで、本体コードは /opt/wake/
- Pi 上では `os.path.exists(CHEAP)` が常に False
- cheap() は設計どおり「判定できないときは止める側に倒す」→ 常に False を返し続けた = 反応的モードの充電が実質死んでいた
- 例外を出さない。ログにもエラーは出ない。9/3〜9/5 の間、反応的モードは一度も発火していない
- もう一方のパス(`import cheap_now` / cheap_gate)は sys.path 経由で両環境から解決できていた
  → CHEAP もそちらの `__file__` から取るよう修正（`cheap_gate.__file__`）
- Pi の実配置を模した一時ディレクトリ（旧パス無し・新パス有り）で再現確認
- テスト2件追加(CheapGatePathTest)。既存63＋新規2、全通過
- ただしこの検査は home PC のテストでは Pi 特有の配置を再現できない → 配備のたびに Pi 上でもテストを走らせる必要が残る
- まだ deploy していない。次は /opt/wake への配備
- 発見の経路: テストでもログでもなく、人間が操作盤を見て「なぜ充電してない?」と聞いたこと

### 夕方 — DHT11 の温湿度を記録・表示（atelier-lab 00c79f0, 18:13）

- アトリエで DHT11(温湿度センサー)をラズパイの GPIO4 に接続
- 最初 RPi.GPIO / lgpio で自分でパルス幅を測る実装。チェックサム不一致・エッジ取りこぼしで4回作り直した
- Linux カーネルに dht11 の IIO ドライバがある。`dtoverlay=dht11,gpiopin=4` を config.txt に足すだけ。
  タイミングはカーネルが見る。読むのは sysfs を cat するだけ
  → /sys/bus/iio/devices/iio:device0/{in_temp_input,in_humidityrelative_input}
- 自作のビットバンギングは全部捨てた
- 記録: log_sensors.py を sensor-log.timer が5分ごとに呼ぶ。USBメモリへ JSONL 追記（日付ごとのファイル）
- USB がマウントされていなければ書かない。マウント前に書くと SDカード側の空ディレクトリに溜まり、
  USB を挿し直した瞬間に見えなくなる（隠れて容量だけ食う）。実際に umount して書かないこと・ゴミが残らないことを確認
- fstab は nofail 付き。USB を抜いても起動は止まらない。USB には既存の Ubuntu インストーラ。消さずに空き領域を間借り（本人確認済み）
- DHT11 は素で時々読めない。`--show` の直後に実行したら読めなかった。ドライバは約2秒キャッシュ。間隔(2.5秒)を空けて最大4回試す

- 実測: 室内 相対湿度 86% / 外 64%。見かけ上「外の方が乾いている」
- 水分量(絶対湿度)に直すと: 室内 21.6 / 外 17.2 g/m³。室内の方が3割多い
- 相対湿度は温度で変わる → 温度の違う室内外を相対湿度同士では比べられない
- 式(Tetens式)は既知の理論値で検算(20℃/100%→17.3、30℃/100%→30.4)
