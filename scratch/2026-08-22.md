### 使用量まわりで分かったこと

- **どのサービスも「消費は測れるが残量は測れない」**
- **Claude Code のトランスクリプトに usage が全部入っている**
  （input / output / cache_creation / cache_read / thinking、ターンごと）
- **`compactMetadata` に preTokens / postTokens がある。** 08-18 は 844,367 → 20,513
- **429 の記録も残る**（`"apiErrorStatus":429`）。リミット値は取れないが**当たった時刻は残る**
- **キャッシュ読が支配的。** 30時間で2億1,751万。出力42万の**500倍**。
  会話が伸びるほど毎ターン重くなる → **重い操作は文脈が小さいうちに**
- **週の区切りは木曜01:00 JST**（本人談）。最初 ISO週=月曜始まりで数えていて**ずれていた**
- **最新1本しか走査していなかった**ので「過去最大の週」が比較にならなかった。
  直したら **今週90万 / 過去最大322万** と、**結論が反転**した（前は今週が2.7倍だと思っていた）
- **claude.ai(ブラウザ)の分は原理的に測れない。** 同じ枠を食うのに記録が無い
- **Sakana は API でもヘッダでも残量を返さない**（`/v1/usage` は404、応答ヘッダも空）。
  **コンソール画面には出る**（5時間6% / 週間3%）。取るなら描画して読むしかない
- Anthropic / OpenAI は**応答ヘッダで取れる**（`anthropic-ratelimit-*` / `x-ratelimit-*`）

### ダンププロンプトは格下げした

- 全文を出力トークンで再生成させるのは**高いうえに不正確**（LLM は逐語再現が苦手）。
  しかも**照合できない**
- **正解は UI のエクスポート**。ChatGPT / claude.ai は設定から、Gemini は Takeout。
  正確・完全・トークン0・機械可読
- **ChatGPT も claude.ai も、サンドボックスから自分の会話履歴を読めない**ので
  「コード実行で出力させる」は成立しない
- プロンプトは「1本だけ今すぐ」の保険に格下げ。`DUMP-PROMPT.md` は残す
